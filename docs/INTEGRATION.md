# Интеграционные и ручные проверки

## Автономные команды

Из корня проекта после Release-сборки:

```bash
dotnet run --project tools/IntellectBot.Checks -c Release --no-build
dotnet run --project tools/IntellectBot.Checks -c Release --no-build -- --gateway
dotnet run --project tools/IntellectBot.Checks -c Release --no-build -- --negative
```

Проверяются настоящий stdio-процесс, каталог, схемы, расписание, ресурс недели,
отказ неизвестному методу и аргументам, отсутствие сервера и запрет записи
без подтверждения. Погода проверяется здесь по схемам; сетевой вызов Open-Meteo
автономная команда не выполняет. Демонстрационная неделя фиксирована проверкой.

Для PostgreSQL:

```bash
bash scripts/test-db.sh
```

Скрипт создаёт отдельный временный контейнер и удаляет только его. Рабочая БД
и volume не используются. Права, транзакции, повторное подтверждение и миграции
проверяются реальной БД. Windows: `scripts/test-db.ps1`.

## Реальные публичные источники

Без LLM-ключа и записи в БД:

```bash
dotnet run --project tools/IntellectBot.Checks -c Release --no-build -- --sources
```

Команда обращается к Open-Meteo и Википедии через отдельный MCP-процесс.
Проверяет Дубай, Питер, Москву, точный выбор ID, повтор из кэша и справочную
выдержку со ссылкой. Длительности выводятся отдельно; это не время ответа LLM.
Нужен доступ к публичным API. Сбой сети считается сбоем проверки и не скрывается.

## Живые LLM-проверки

Нужен `.env` с рабочим API. Эти команды расходуют квоту:

```bash
dotnet run --project tools/IntellectBot.Checks -c Release --no-build -- --llm
dotnet run --project tools/IntellectBot.Checks -c Release --no-build -- --decision-llm
```

Они не выполняют запись напоминания. Наличие HTTP 200 само по себе не подтверждает корректность аргументов: далее выполняется отдельная проверка.

## Ручной сценарий Telegram

Перед запуском остановить другой процесс с тем же токеном. Для каждой модели:

| Проверка | Ожидаемое поведение |
|---|---|
| «Расскажи про SOLID и GRASP в C# с примерами» | Разбор по существу; код отдельными моноширными блоками; нет оборванного вступления |
| «Что такое кортеж? Приведи пример» | Определение, объяснение и пример, а не повтор слова |
| «Какая погода в Москве?» → «один» | Понятный список при неоднозначности, затем данные именно выбранного места |
| «А во втором варианте?» | Другой номер исходного списка, без перенумерации |
| Уточнение «Москва, Россия» | Выполнение либо конкретный вопрос о регионе; без выдуманных данных |
| «Сравни SOLID и GRASP таблицей» | Вместо строк с `|` — читаемые карточки; код не изменён |
| «Кто такой Николай Дуров?» | Сведения из справочного инструмента со ссылкой либо уточнение, без выдуманной биографии |
| Перевод на немецкий | Русские названия языков, перевод, корректное копирование |
| Часовой пояс Asia/Tokyo → напоминание на прошедшее сегодня время | Уточнение или понятный отказ, без кнопок сохранения прошедшего времени |
| «Напомни завтра в 18:00 проверить код» | Просмотр точных параметров и кнопки подтверждения/отмены |
| Отправить тот же запрос напоминания новым сообщением | Сообщение, что оно уже существует; новой записи нет |
| Ответить «да» на просмотр | Повторно показаны кнопки; без нажатия запись не исполняется |
| Подтвердить дважды | Одна запись, понятный ответ о повторном нажатии |
| Отменить или нажать после пяти минут | Запись не создаётся |
| Настройки → Расписание | Просмотр только своих занятий; изменение после подтверждения; прошедшая дата отклоняется |
| Напоминание на завтра 09:00 → подтверждение → `/why` | В аргументах те же местные 09:00, а не UTC; время до минут, статусы и безопасные аргументы |
| «Новый чат» | История очищена, настройки и личные записи сохранены |
| Смена модели/креативности | Новые параметры применяются, история сохраняется |

Повторить погоду и личные операции с другого аккаунта: история, списки городов,
подготовленные действия и расписание не должны смешиваться.

## Проверка квоты

Не нужно специально исчерпывать аккаунт. Если провайдер вернул ограничение:

- при известной короткой паузе бот продолжает печатать и ожидает в пределах бюджета;
- повтор после 429 выполняется не более одного раза;
- после полученного MCP-результата повторите то же сообщение или номер в течение
  двух минут: повторный вызов инструмента не нужен;
- при долгом ограничении показывается сообщение об ограничении конкретного запроса; выбранная модель не меняется.

В журнале есть request_id, модель, статус, длительность и доступные счётчики
токенов/остатков. Полные запросы, ответы, ключи и скрытые рассуждения не пишутся.

## Docker

```bash
bash scripts/run-bot-docker.sh itmo-local-fb4295feeb-db-1
docker exec intellect-bot dotnet IntellectBot.dll healthcheck
docker logs --tail 100 intellect-bot
```

Ожидаются подключение PostgreSQL, обнаружение MCP и polling. Health проверяет
PostgreSQL и polling; живую LLM и Open-Meteo подтверждает ручной сценарий.

Фактически выполненные проверки: [VALIDATION.md](VALIDATION.md).
## Контекст, ссылки и перевод

- Длинный ответ про SOLID/GRASP → смена модели → «сравни их»: тема сохраняется.
- Перевод на немецкий и обратно: реальные языки в заголовке, только перевод в
  копируемом блоке, без исходника и Markdown-ограждений.
- «Кто такой Стив Джобс?» и «Кто такой Джон Крамер?»: нет списка посторонних фильмов.
- «Дай ссылку на Telegram Павла Дурова»: ссылка из Wikidata либо честное отсутствие.
- Погода в Питере, Самаре, Мичуринске: корректное место, русские подписи;
  уточнение остаётся допустимым при реальной неоднозначности.
- Справочный ответ: естественный порядок имени, короткие разделы и источник;
  предпросмотр ссылки не появляется. Ширина текста зависит от клиента Telegram.

## Последние проверки интерфейса

- Перевести русский текст на немецкий, затем «теперь на английский»: направление
  меняется, заголовок обычный, весь перевод моноширный и копируется без исходника.
- Выбрать другой пояс из списка: ✓ переносится только на выбранную кнопку.
  Для собственного пояса вне списка ни один город не отмечается.
- Запросить простую формулу с дробью, корнем и степенью: нет необработанной
  простой LaTeX-разметки; такой же текст внутри программного кода не меняется.
- В Europe/London подготовить напоминание на завтра в десять: просмотр,
  подтверждение и `/why` показывают 10:00 в этом поясе, без ручного сдвига UTC.
- Проверить текст напоминания: он соответствует просьбе, без добавленных слов
  и символов других алфавитов. Для прошедшего времени требуется уточнение.
