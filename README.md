# intellect_bot

AI-ассистент студента в Telegram на C# и .NET 10. Объясняет программирование, проверяет код и переводит текст. Пользователь выбирает режим и уровень креативности в настройках; история и настройки сохраняются в PostgreSQL.

## Требования

- .NET SDK 10;
- Docker Desktop или Docker Engine с Compose v2;
- Telegram-бот, созданный через BotFather;
- ключ OpenAI-совместимого LLM API;
- Git для публикации проекта.

## Настройка и запуск

Откройте корень репозитория в VS Code. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `LLM_API_KEY`. При необходимости задайте прокси Telegram. Все параметры перечислены в `.env.example`.

Первоначальная настройка локальной БД:

```bash
bash scripts/start.sh --setup-only
```

Windows PowerShell: `.\scripts\start.ps1 --setup-only`.

Скрипт запросит недостающие ключи, сгенерирует пароль базы и выполнит проверку `SELECT 1`. По умолчанию отдельная локальная БД слушает `127.0.0.1:5433`, а служебная проверка приложения — `127.0.0.1:8081`. Параметры из существующего `.env` имеют приоритет над этими примерами. Для своей уже запущенной PostgreSQL укажите её адрес и учётные данные, затем используйте обычный запуск приложения.

```bash
dotnet restore --locked-mode
dotnet build -c Release --no-restore
dotnet run --project src/IntellectBot -- dbcheck
dotnet run --project src/IntellectBot
```

`RunWorkingDirectory` в проекте задаёт корень репозитория для `dotnet run`. `.env` должен лежать рядом с `IntellectBot.sln`.

В отдельном терминале:

```bash
dotnet run --project src/IntellectBot -- healthcheck
```

Остановка — Ctrl+C. Не запускайте несколько экземпляров polling с одним токеном.

Управление локальной БД:

```bash
bash scripts/start.sh status
bash scripts/start.sh logs
bash scripts/start.sh stop
```

Остановка сохраняет данные в volume. Compose-проект определяется по пути папки; перенос папки меняет его имя. Для запуска по F5 предусмотрены настройки VS Code; PostgreSQL должен быть запущен заранее.

## Управление ботом

| Команда | Действие |
|---|---|
| `/start` | Главное меню |
| `/settings` | Настройки режима и уровня креативности |
| `/reset` | Очистка памяти диалога |

В главном меню две кнопки: «Сброс памяти» и «Настройки». В настройках верхний ряд содержит значения 0, 0.3, 0.7 и 1; ниже находятся два режима, которые сейчас не выбраны. Возврат в меню доступен при открытии настроек из меню. Сообщение меню обновляется на месте.

Режимы:

- Обучение — объяснение программирования; используется по умолчанию.
- Проверка кода — поиск ошибок и предложения исправлений.
- Перевод — перевод текста с направлением, выбранным для каждого сообщения.

Режимы выбираются кнопками. Команды `/study`, `/review`, `/translate` и `/temperature` отсутствуют. Смена режима очищает историю, но сохраняет уровень креативности. Сброс очищает только историю текущего пользователя и сохраняет настройки.

В переводе можно написать «На немецкий: Доброе утро». Без указания языка используется русский ↔ английский; для остальных языков бот уточняет направление. Ответ содержит заголовок языков и перевод в моноширном формате `<code>`. Возможность копирования зависит от клиента Telegram.

Бот работает только в личном чате и принимает текст. На вложения отвечает объяснением. Во время генерации отправляет индикатор «печатает…»; при быстром ответе клиент может не успеть его показать. Команды и кнопка меню регистрируются при запуске. Описание, аватар и картинка до запуска настраиваются через BotFather.

## Архитектура

| Папка | Назначение |
|---|---|
| `Configuration` | Настройки, env-файлы, проверка значений |
| `Domain` | Режимы, диалог, ограничение контекста, интерфейсы |
| `Data` | PostgreSQL, схема, история и настройки |
| `Llm` | Клиент модели и безопасные ошибки |
| `Telegram` | Bot API, обработчики, меню и форматирование |
| `Prompts` | Системные инструкции трёх режимов |
| `Hosting` | Запуск, polling, health и остановка |
| `Infrastructure` | Логи, блокировки, локальные и облачные команды |

Код находится в `src/IntellectBot`, тесты — в `tests/IntellectBot.Tests`. Используются Npgsql, HttpClient, System.Text.Json, ASP.NET Core и xUnit. Зависимости закреплены lock-файлами.

## Данные и безопасность

Пул PostgreSQL создаётся один раз. Схема создаётся идемпотентно и не удаляет существующие данные. SQL-параметры передаются отдельно от запросов. Пара сообщений user/assistant сохраняется транзакционно только после успешного ответа модели.

По умолчанию в контекст передаются последние 12 сообщений целыми парами. Если сумма длин инструкции, истории и запроса превышает 6000 Unicode-кодовых точек, самые старые пары удаляются из передаваемого контекста. Инструкция и текущий запрос не обрезаются; слишком длинный запрос отклоняется. История в БД при этом сохраняется. Ограничения задаются через конфигурацию.

Запросы одного пользователя выполняются последовательно, разных — независимо. Ответы разбиваются по UTF-16 без разрыва emoji: обычные по 4000 единиц, перевод по 3900 с заголовком. Ошибки сети, лимита и формата ответа преобразуются в русские сообщения. Повторных запросов к модели при ошибке нет.

Переменные процесса имеют приоритет над `.env`; подстановки `${...}` не выполняются. Секреты не включаются в Git и Docker-образ. Логи содержат ID запроса, модель, длительность и код ошибки; содержимое диалога и ключи не записываются. Прокси Telegram задаётся отдельно, без прямого обхода при сбое, и не применяется к LLM.

`/health` доступен только на loopback и проверяет работу polling и `SELECT 1`. Доступность Telegram и LLM при сетевых сбоях проверяется по журналу. Активный webhook не удаляется автоматически и блокирует запуск polling.

## Проверки

```bash
dotnet restore --locked-mode
dotnet build -c Release --no-restore
dotnet test -c Release --no-build
dotnet format whitespace . --folder --verify-no-changes
bash scripts/test-db.sh
```

Windows вместо последней команды: `.\scripts\test-db.ps1`. PostgreSQL-тесты используют отдельный временный контейнер. Обычные тесты выполняются без настоящих Telegram и LLM API. План ручной проверки — `docs/VALIDATION.md`.

## Docker и облако

```bash
docker build -t intellect-bot .
docker run --rm intellect-bot --help
```

Для серверного запуска подготовьте `.env.cloud`:

```bash
docker compose --project-name intellect-csharp --env-file .env.cloud --profile cloud up -d --build --wait
```

Контейнер приложения работает от непривилегированного пользователя. PostgreSQL и health в серверной конфигурации наружу не публикуются.

Развёртывание в Yandex Cloud:

```bash
bash scripts/deploy.sh up --ssh-cidr YOUR_PUBLIC_IP/32
bash scripts/deploy.sh status
bash scripts/deploy.sh logs
bash scripts/deploy.sh stop
bash scripts/deploy.sh start
bash scripts/deploy.sh access --ssh-cidr YOUR_NEW_PUBLIC_IP/32
```

Windows: `.\scripts\deploy.ps1`. Требуются OpenSSH, аккаунт Yandex Cloud с биллингом и внешний прокси Telegram. CLI `yc` при необходимости устанавливается официальным установщиком; вход выполняется через `yc init`.

Состояние ресурсов и SSH-ключ находятся в `.deploy`; храните резервную копию. Секреты передаются через stdin SSH. Ресурсы проверяются по метке владельца и каталогу. Общая сеть default не удаляется. `destroy` требует явного подтверждения и удаляет собственную ВМ с диском БД; `stop` сохраняет диск, который продолжает тарифицироваться.

Публикация и тег лабораторной — `docs/GITHUB.md`. Эксперимент с четырьмя значениями temperature — `docs/lab1-experiment`.
